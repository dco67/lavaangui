# lavaangui experimental advanced-analysis extension

## Developer change log (working document, English)

**Baseline:** the supplied lavaangui development sources, version 0.4.0.9000, with the author's original DESCRIPTION and NAMESPACE. Original source archive and prior cumulative releases are preserved. This is a development proposal, not an official release of lavaangui. No change in authorship or licensing is implied.

### Rationale and integration approach

The extension adds analytical workflows to the Extended Results area (`More Results`) without replacing the single-model graphical editor or the Svelte/Cytoscape frontend. Completed GUI model specifications and options are captured together with a fingerprint of the current data. New Shiny modules refit validated specifications through lavaan. Results are shown as tables, diagnostic text, reproducible R scripts and read-only diagrams; CSV/SVG/JSON downloads are optional. No user-uploaded R source is executed. The original `.lvm` format is unchanged.

### This release: scope and implementation details

- `R/advancedAnalysisCore.R`: new ordinal plan and view validation; optional fit function for cfa; same-parameterization WLSMV comparisons support theta for the ordinal workflow, retaining existing single-group delta path. Existing continuous estimation paths unchanged in intent. Ordinal support deliberately limited to simple, fully ordered CFA with 3+ indicators per factor and 4–12 observed categories per indicator, matching category support in groups after listwise deletion. No binary/three-category, mixed continuous/ordinal, residual dependence, partial ordinal invariance, higher-order or structural ordinal model workflow. Counts of expected df increments are checked, not substituted for fit results. The optional `semTools` dependency is declared in DESCRIPTION/Suggests; NAMESPACE does not change. The generated syntax uses `lavaan::cfa` and is exported as actual fitted syntax, so the exported analysis need not regenerate it.
- `R/componentAdvancedAnalysis.R`: explicit third analysis mode and optional strict ordinal stage; view state bridge, status text and compatible restore workflow. Results remain independent of the main editor.
- `R/advancedGroupDiagram.R`, `inst/www/advanced-group-diagram.js`: bounded, label-keyed last-view recipe; client coordinates are clamped to the locally generated layout; no uploaded markup or executable code is inserted. Stage and result token prevent reuse of a stale view in another analysis. Last-view only; no distinct saved layouts for every stage. Diagram inference caveat retained; ordinal thresholds appear in the parameter table, not on arrows.
- `tests/manual/advanced_ordinal_views.R`: native comparison of all five stages and corrected tests, script replay, scope checks, v1/v2 JSON, invalid view and UI construction. `tests/manual/advanced_view_browser.py`: browser-only state capture/restore, stale-token isolation, malformed-view fallback and restored arrowhead checks. Previous regression scripts remain available.
- `INVARIANCE-ORDINALE-ET-VUES.md`: French installation and test instructions for the user, including the supplied synthetic data and model 07.

### Testing and limitations

No R executable, Quarto or live Shiny server is available in the authoring container. R source checks are lexical checks, not R parsing or execution. Browser tests use synthetic coefficients and a simulated Shiny input bridge, not live fits. The release is not production-validated until the user runs the tests and manual UI recipe locally. Version 2 project files can contain aggregate sensitive results and must be handled accordingly, even without individual rows. Compatibility is strict: a different model or data fingerprint prevents restore; re-estimation is explicit. The original package author's design decisions and existing user workflows should be respected during review.

## Increment 8 — descriptive group contrasts and equality-constraint diagnostics

- The existing Path diagram viewer now offers `Two groups + difference (second minus first)`. Two group-specific panels and a third descriptive contrast use the same layout and controls. Subtraction uses unrounded coefficients, preserves missing values (including absent parameter rows), and includes explicit signs, contrast order and a non-inferential caveat in the standalone SVG. Raw latent contrasts require a justified common scale. No contrast p-values or CIs are implied by the diagram. The existing v2 JSON view recipe accepts `difference`; prior views remain readable, but older software cannot interpret this new mode. Main editor, fitting engine, existing tests and native `.lvm` format are unchanged.
- The `Constraint diagnostics` result tab computes ordinary ML score tests and EPCs using one `lavaan::lavTestScore(..., release=i, univariate=TRUE, epc=TRUE, standardized=FALSE)` call per explicit between-group equality. It maps constraint labels to actual parameter rows and groups, verifies the native result, displays Holm-adjusted p-values for the listed family and two group-specific expected changes for the selected equality. Scope: simple continuous two-group CFA with at least three indicators per factor, ML with conventional test/SE, listwise deletion, converged/admissible warning-free fit, at most 100 explicit equality constraints. Enforce two common anchors after hypothetical release (loadings for metric, joint loading/intercept anchors for scalar/strict). Refuse or flag unsupported constraints, invalid results and warnings. No automatic releases, no fit changes, no score testing for MLR/WLSMV or structural/ordinal models in this increment. Residual variance equality diagnostics are inspectable; the partial-invariance UI still releases only loadings and intercepts. CSV exports of score results and selected EPC; not yet in companion JSON or generated script (the index and native call are documented). No new dependencies or changes to package metadata.
- Tests: `tests/manual/advanced_difference_browser.py` checks subtraction before rounding, zero, missing values and missing rows, sign reversal, shared coordinates, exported SVG and saved view. It passed in Chromium with synthetic data (29 additional arrowhead inspections, zero detected overlaps or JS errors). Existing browser tests passed (230 + 44 arrowhead inspections). `tests/manual/advanced_score_differences.R` compares native ML scores/EPCs and verifies anchor guard, invalid scope, JSON and UI construction; it has not been executed because R/Shiny is unavailable here. R lexical/static checks only. User acceptance and actual statistical/interactive regression tests remain required.
- New French recipe: `DIAGNOSTICS-ET-DIFFERENCES.md`. Use the existing test bank's `01_AFC_continue.lvm` and `banc_lavaangui.csv`. Diagnose `f1=~x3` in Metric; after that loading is released, diagnose `y3~1` in Partial scalar; with both released inspect `y4~~y4` in Partial strict. Results are expected from the simulation, not claimed as computed by lavaan in this environment.
- Remaining work: indirect/total effects and between-group contrast uncertainty; complete HTML analysis report; an integrated navigation/usability review (clearer action sequence and discovery of advanced controls); full local validation; English author-facing technical handoff and package documentation; French Quarto-manual additions with targeted real SVG/captures, examples, exercises and solutions. The user prefers to supply selected figures only when needed for the manual.

## Increment 9 — derived effects, offline reports, navigation and acceptance candidate

- Added `R/advancedEffectsReport.R`: raw direct, individual indirect, total indirect and total path effects from the already fitted `Free regressions` model; directed acyclic graphs only (up to 30 structural variables and 100 paths). Pairwise contrast is explicitly second minus first. Analytical product gradients and the full fitted free-parameter covariance (`lavInspect(f, "vcov")`) provide normal delta-method 95% intervals and unadjusted two-sided Wald p-values; use the model's ML or MLR covariance, retaining any cross-group dependence. Check free indices against regression SEs, identical regression topology, admissibility and warnings. No refit during viewing, no feedback, ordinal, standardized-effect comparison or bootstrap; structural zeros are not tested. Latent effects require a defensible common measurement scale; effects are model-based and not automatically causal. A native-defined-parameter regression test is supplied but has not been executed here.
- Offline HTML reports for both model comparison and multigroup analyses: fitted configurations without the data argument, fit/used-count tables, formal tests or explicit refusals, fit messages, all available raw and standardized parameter tables, current optional score/EPC and effects, and reproducible base script plus optional diagnostic recipes for the same extension. The multigroup report embeds the trusted existing diagram renderer and an escaped data payload for the most recent compatible view (default first usable fit if none). Interactive SVG export works offline. No individual data rows, executable uploaded code or external requests; aggregate values may be confidential. Report is a snapshot, not a saved fit or import format. The companion JSON and .lvm remain unchanged; score/effect optional outputs are exported in CSV/HTML, not restored from JSON.
- UI: retained frequent Fit table, Selected estimates and Path diagram; grouped secondary tabs under Advanced diagnostics (Constraint diagnostics; Indirect & total effects) and Export & restore (Save / restore; Analysis script; HTML report). Model Comparison groups script/report under Export. Added workflow banners, collapsed lengthy specification views, visible current-estimate status and mode-specific diagnostics default. Scoped to advanced modules; original editor unchanged. This navigation supersedes historical guide tab locations; mapping provided in `VALIDATION-FINALE-EXTENSION.md`.
- Acceptance candidate: `tests/manual/advanced_effects_reports.R` (native lavaan ML/MLR defined effects, SE/CI/p, contrast reversal, zero path and invalid selections, multi-path sums/covariance, actual HTML serialization, escaping and UI construction), `tests/manual/run_advanced_validation.R` (six isolated R subprocesses and retained logs), `tests/manual/advanced_report_browser.py` (offline embedded renderer, synthetic fixture; optional real report). All historical Chromium tests pass; offline synthetic shell passes without Shiny/network. Independent conditional regression/delta reference on supplied CSV. R/Shiny not available in authoring environment, so all actual R computations, report serialization and live UI acceptance remain pending. Prior R test scripts source the new helpers when constructing UI. No new dependencies; no package metadata changes.
- Ready for local acceptance, not a certified release. Next handoff after local test evidence: English author-facing report/source review, English package help/examples/developer notes, French Quarto update with requested figures and exercises. The guide lists unsupported cases and acceptance steps. Do not represent the original author as endorsing the extension.

## Acceptance run 1 and targeted compatibility repair

- The user's Windows 11 / R 4.6.0 / lavaan 0.7-3 run on 26 November 2026 returned three PASS and three FAIL. `advanced_diagrams.R`: 318 native parameter-to-edge matches. `advanced_ordinal_views.R`: all five expected df values (16, 22, 26, 30, 36), corrected native comparisons, script replay, saved-view round trip and UI construction passed. `advanced_effects_reports.R`: native ML/MLR estimates, contrasts, multiroute covariance, refusal checks, actual HTML generation and navigation passed.
- `advanced_analysis.R` and `advanced_wlsmv_projects.R` stopped at the same nesting-guard message although fitted models converged without warnings and had a one-df difference. The old `all.equal()` compared a difference retaining lavaan's `lavaan.vector` class with an ordinary number. The repair converts scalar df values to plain numeric values, requires finite nonnegative integral df, a positive integer restriction count, and exact numerical agreement. The diagnostic now includes both df values and the detected count. Structural, compatibility, convergence, warning and robust-test guards are unchanged.
- `advanced_score_differences.R` stopped at the ordinary-ML scope guard. lavaan 0.7-3 added the model-based normal-theory Browne residual statistic alongside the standard ML chi-square by default (https://lavaan.ugent.be/history/dot7.html; https://rdrr.io/cran/lavaan/man/lavOptions.html). The guard now admits exactly the legacy standard test set or the new standard-plus-Browne set, with ML, standard SE and listwise deletion. It does not admit scaled/robust, ordinal or otherwise unsupported tests. The ordinary score/EPC calculations remain unchanged.
- Added assertions on classed df scalars, mismatched/reversed/invalid df, ML option sets and refused robust/nonstandard options, native ML/MLR LRT agreement. Existing tests, including native WLSMV and score/EPC comparisons, are retained. Only `R/advancedAnalysisCore.R` changes in runtime source; no metadata, interface, graphics, fitting code, report code or data modifications.
- The causes are supported by source inspection and version documentation; the repaired code has not yet been executed in R. Repeat the full six-script acceptance run and complete the live Shiny checklist before describing the extension as validated. The original first-run failures are retained in this history.
